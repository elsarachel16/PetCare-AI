# PetCare AI: Agentic Multi-Agent Pet Care Management and Personalized Care Planning System

A LangGraph multi-agent app with a website. Add a pet profile, then ask in plain English for a care
plan, grooming schedule, feeding times, or appointment reminders. A supervisor routes each request
through specialist agents, saves reminders, keeps a JSON report of every run, and lets you change the
plan by chatting ("I won't be home on Wednesday").

It is built on the same architecture as your **AI Trip Planning Concierge**:
LangGraph + LangChain + Ollama (`qwen2.5:3b`), a shared state, a routing agent, structured extraction,
a supervisor with specialist agents, a tool-using ReAct follow-up agent with memory, and JSON reports.

PetCare AI organises care. It is **not veterinary advice**: it never diagnoses, prescribes, or sets food quantities,
and any health concern is referred to a vet.

## Run it

```bash
# 1. (optional but recommended) local model, same as your Trip Concierge
ollama pull qwen2.5:3b

# 2. start the site
./run.sh            # macOS / Linux
run.bat             # Windows
```

Open **http://localhost:8000**. On the empty Today page, choose "Try with a sample dog (Bruno)".

Or do it by hand:

```bash
python -m venv .venv && source .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install -r requirements.txt
cd backend && python -m uvicorn main:app --reload
```

**Works without Ollama.** If Ollama or the model isn't found, the app runs in *rules mode*: every plan is
still generated by the built-in care rules, only the AI-written tips and free-form answers are skipped.
The Ask page shows which mode is active. Force rules mode with `PETCARE_USE_LLM=0`.

### Command-line demo (like your `main.py`)

```bash
cd backend
python cli.py                 # sample requests for Bruno, printing the agent path
python cli.py --interactive   # type your own requests
python cli.py --rules-only    # no Ollama needed
```

### Tests

```bash
cd backend && pytest -q       # 13 tests, no Ollama needed
```

## How a request flows

```text
Pet Care Request
      |
 Pet Routing Agent  ----- follow-up on an existing plan? ------> Follow-up Pet Assistant --> Report
      |                                                            (edits plan, or ReAct agent
 Pet Profile Extraction Agent                                       with tools + memory answers)
      |
 Care Assessment Agent
      |
 Supervisor Agent  <----------------------------+
      |                                          |
      +--> Exercise | Grooming | Feeding | Appointment & Reminder | General Care agent
      |
 Care Plan Agent  -->  Report Agent  -->  JSON report
```

The supervisor queues specialists for the intent and dispatches them one at a time, so the **Agent workflow**
panel on the Ask page shows every hop. A full plan runs Exercise, Grooming, Feeding, and Appointment agents.
A grooming-only request runs just the Grooming agent.

Intents: `care_plan`, `exercise`, `grooming`, `feeding`, `vaccination_reminder`, `vet_appointment`,
`pet_profile`, `general_question`, `urgent_health`, `followup`.

## From Trip Concierge to PetCare AI

| Trip Concierge | PetCare AI | What changed |
|---|---|---|
| `state.py` (`TripConciergeState`) | `backend/state.py` (`PetCareState`) | Same shared TypedDict; adds reducers so agents can append trace steps and results |
| `llm.py` (`get_llm`) | `backend/llm.py` | Keeps `get_llm()`; adds an Ollama health check and safe fallbacks so the app runs without a model |
| `phase2_routing.py` (classify + desks) | `agents/routing.py` | Keyword rules first, LLM only when nothing matches; detects health concerns and follow-ups |
| `phase3_extraction.py` (`TripRequest` + `JsonOutputParser`) | `agents/pet_profile.py` | `PetProfile` Pydantic model and the same `prompt \| llm \| parser` chain, plus rule-based extraction of dates, days, and intervals |
| `phase4_feasibility.py` (budget screening) | `agents/care_assessment.py` | Budget per person per day becomes life stage, size, and exercise/meal/grooming targets (`tools/pet_calculator.py`) |
| `supervisor_agent` + `route_from_supervisor` | `agents/supervisor.py` + `graph/petcare_graph.py` | Same conditional routing, now a loop: dispatches each queued specialist, then the planner |
| Cost Optimization / Premium Planning agents | `agents/exercise.py`, `grooming.py`, `feeding.py`, `appointment.py`, `general.py` | Specialist agents |
| `recommendation_agent` | `agents/recommendation.py` | Merges specialist output into one weekly plan and calendar |
| `tools.py` (`cost_calculator`, `destination_info`) | `tools/pet_tools.py` | `care_calculator`, `pet_care_info`, `current_care_plan` |
| `phase5_followup_agent.py` (`create_react_agent` + `MemorySaver`) | `agents/followup_agent.py` + `agents/followup.py` | Same ReAct agent with one memory thread per pet. Plan edits are rule-based so they stay reliable with a 3B model |
| `phase6_report.py` | `agents/report.py` + `reports.py` | A JSON report per request, with the full agent trace |
| `main.py` | `backend/cli.py` (demo) and `backend/main.py` (API + website) | |

## Website pages

- **Today**: the pet's collar tag, today's checklist from the plan, and upcoming reminders.
- **Care plan**: the weekly calendar (exercise, grooming, feeding, health) plus details for each area.
- **Ask PetCare AI**: chat, with the live agent workflow beside it.
- **My pets**: add, edit, and delete profiles.
- **Reminders**: add, complete (repeating ones roll forward), and delete.
- **Reports**: download the JSON report for any request.

## API

| Method | Path | Purpose |
|---|---|---|
| GET | `/api/health` | Server and Ollama status |
| GET / POST | `/api/pets` | List or add pets |
| PUT / DELETE | `/api/pets/{id}` | Edit or delete a pet |
| GET | `/api/pets/{id}/plan` | Latest saved plan |
| POST | `/api/chat` | Run the agent graph: `{"message": "...", "pet_id": "..."}` |
| GET / POST | `/api/reminders` | List or add reminders |
| POST / DELETE | `/api/reminders/{id}/done`, `/api/reminders/{id}` | Complete or delete |
| GET | `/api/reports`, `/api/reports/{id}`, `/api/reports/{id}/download` | Reports |
| GET | `/api/graph` | Mermaid diagram of the LangGraph workflow |

Interactive docs are at http://localhost:8000/docs.

## Notes

- Care numbers (exercise minutes, brushing frequency, meals per day) come from general guidelines in
  `tools/pet_calculator.py`. Tune them there, the way you tuned the budget thresholds in Trip Concierge.
- Meal plans set times only. Portion sizes are left to the food label and your vet.
- `create_react_agent` shows a deprecation notice in some newer `langgraph` versions. It still works,
  the same as in your Trip Concierge.
- The site loads two Google Fonts. Offline, it falls back to system fonts.
